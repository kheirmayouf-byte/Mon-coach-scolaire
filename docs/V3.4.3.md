# Version 3.4.3 — connexion du site à l’abonnement local

Le site en ligne propose Continuer avec ChatGPT, Tester la connexion et un choix de modèle réellement accordé au compte. Les questions et quiz du site passent par le client ChatGPT local existant, sans clé API payante ni transfert des jetons ChatGPT au navigateur ou à Supabase.

## Utilisation

1. Fermer une ancienne version Windows, puis ouvrir Mon Coach Scolaire 3.4.3 sur le même ordinateur que le navigateur.
2. Dans le site, se connecter au compte parent puis ouvrir Mon compte → Mon IA → Continuer avec ChatGPT.
3. Autoriser l’accès local du navigateur s’il est demandé. Valider le rattachement au compte parent dans la fenêtre native Windows. Autoriser ensuite ChatGPT si la connexion n’existe pas encore.
4. Depuis le site, tester la connexion et choisir un enfant pour discuter avec le coach.

L’application Windows doit rester ouverte. Le site ne fonctionne pas avec ce relais depuis un autre ordinateur, un iPhone ou un iPad. Un service indépendant pour ces appareils n’est pas inclus dans ce correctif.

## Limites d’accès

Le serveur écoute seulement 127.0.0.1:4174. Il exige le Host exact et l’origine HTTPS du site, refuse les autres méthodes et chemins, limite le corps et le nombre de requêtes. Le navigateur obtient de Supabase une preuve signée après vérification du parent et de son foyer. Cette preuve expire après 45 secondes et est liée à la méthode, au contenu de la demande et à un nonce à usage unique. Le relais fait vérifier cette preuve par le service fixe Supabase et refuse son rejeu. Le jeton de session parent ne quitte pas Supabase pour le relais. Le premier rattachement exige une confirmation native, puis la correspondance du même utilisateur, foyer et profil ChatGPT. Un changement de profil ChatGPT invalide le lien. Le rattachement est chiffré par le coffre Windows ; il peut être retiré dans le site ou le client natif. Aucun jeton ChatGPT ne fait partie des réponses HTTP.

Le site mémorise seulement le choix d’utiliser le relais pour ce compte parent. Aucun sondage du relais avant cette activation ; les connexions suivantes peuvent vérifier un rattachement déjà autorisé. Les navigateurs peuvent demander leur propre autorisation d’accès local.

## Vérification

Tests de transport, parcours web avec session parent et fournisseur simulés, contexte limité au bon enfant, absence de recours à une API payante, refus des mauvaises origines/hôtes, approbation native, compte différent, changement de profil et retrait persistant du rattachement. Compilation web et Windows et suite du SDK existant.

Les tests utilisent des comptes fictifs. La permission réseau du navigateur, la confirmation Windows et une réponse avec un vrai abonnement restent à confirmer sur le poste utilisateur. L’accès à l’aperçu navigateur local est bloqué par un réglage enregistré ; aucun contournement n’a été utilisé.
